# Expo + React Native (Android)

Opinionated guide for building Android apps with **Expo SDK 50+** and **React Native 0.81+**, TypeScript, Expo Router, and EAS Build. Targets the **New Architecture** (Fabric/TurboModules, enabled by default in SDK 50+).

## Stack defaults

- **Language**: TypeScript (`strict: true`). No plain JS.
- **Routing**: Expo Router (file-based, `app/` directory). Enable typed routes.
- **State**: Zustand for client state; TanStack Query for server cache when the app grows beyond manual fetch-in-effect.
- **Server state**: thin async service modules (`src/services/`); components call hooks/stores, never `fetch` directly.
- **Secrets/tokens**: `expo-secure-store` (Android Keystore). Never AsyncStorage for anything sensitive.
- **Push**: `expo-notifications` + FCM. Upload server credentials via EAS.
- **Builds**: EAS Build + Submit. `expo-dev-client` for native debugging (not Expo Go when custom native code/config plugins are used).
- **Package manager**: match the repo (Yarn/NPM/pnpm). Don't switch managers mid-project.

## Workflow

1. **Understand the project first.** Read `package.json`, `app.json`, `eas.json`, `tsconfig.json`, `babel.config.js`, `metro.config.js`. Note SDK version, enabled plugins, path aliases, and whether `newArchEnabled` is on.
2. **Read the domain.** If a `CONTEXT.md` exists, read it for vocabulary and constraints. Mirror existing naming (e.g., Spanish API fields if the backend uses them).
3. **Follow existing structure.** Mirror the layering you find — typically `app/` (routes), `src/screens`, `src/services`, `src/store`, `src/types`, `components/`, `hooks/`, `constants/`.
4. **Make changes.** Prefer editing over creating. Use path aliases (`@/...`) if configured.
5. **Verify.** `npx expo start`, `yarn lint`, `tsc --noEmit`. Run on an Android device/emulator with `yarn android`.
6. **Don't commit secrets.** `google-services.json`, `.env`, Auth0 client secrets stay local.

## Key decisions (one level deep)

- **Expo Go vs expo-dev-client**: Expo Go can't use custom native code or most config plugins. If the app uses `expo-notifications` channels, background tasks, or native mods, use `expo-dev-client` + EAS Build (development profile).
- **New Architecture**: enabled via `"newArchEnabled": true`. Reanimated 3+, Screens, SVG all support it. Test thoroughly on Android — some older native libs break.
- **CNG (Continuous Native Generation)**: `ios/` and `android/` folders are generated by `npx expo prebuild`. Don't edit them directly; patch via config plugins. Commit them only if you've ejected from CNG.
- **React Compiler**: if enabled (`"experiments": { "reactCompiler": true }`), keep components idiomatic — avoid manual memoization hacks the compiler already handles.
- **Forms**: React Hook Form + Zod for anything beyond 2 fields.

## Anti-patterns

- `fetch` directly in components (use a service + hook/store).
- AsyncStorage for tokens (use SecureStore).
- Editing `android/` native folders when on CNG (use a config plugin).
- `Alert.alert` for every error (use inline UI + a toast/snackbar).
- Inline styles / `StyleSheet.create` per render.
- Ignoring Reanimated worklet warnings (they mean animation runs on the JS thread).
- Hardcoding API URLs (use `expo-constants` or a `src/config.ts`).
- Switching package managers or SDK versions mid-feature.
